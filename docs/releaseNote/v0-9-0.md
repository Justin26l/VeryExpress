# v0.9.0

## Broke

- `UserAuthProfiles.oauthId` → `providerUserId`. `(provider, providerUserId)` is now the
  account-linking key and carries a composite unique index; nothing enforced it before.
- App code that reads `oauthId` must be updated.
- Details: [`docs/features/externalIdentity.md`](../features/externalIdentity.md).

## New

- **External identity (broker SSO, Firebase).** `POST /api/auth/external` verifies a broker ID token
  against the issuer's JWKS and provisions the vex identity; every token stays vex-issued, and no
  broker SDK or client secret enters the server. **Off by default** — turn it on in
  `vex.config.json → auth.externalIdentity`, then `npm install`. Details:
  [`docs/features/externalIdentity.md`](../features/externalIdentity.md).
- `POST /api/auth/token` now consumes `sessionCode`, so it is single-use.
- The login page renders the broker's buttons, and the home page shows a login link for broker-only
  apps. `/delete_account` states the sign-in prerequisite. Details:
  [`docs/features/accountDeletion.md`](../features/accountDeletion.md).

## Upgrade

1. `npm install` — `firebase` is a new dependency.
2. Re-run `vex` — the schema migration renames the property.
3. Migrate the column and its constraint: [`docs/features/externalIdentity.md`](../features/externalIdentity.md#upgrading-from-08x).
4. Update app code that reads `oauthId`.
5. Keep the app's `package.json` at `0.9.0` or later — a lower version re-runs the migration on every
   generation.
