# v0.9.0

## Breaking — `UserAuthProfiles.oauthId` → `providerUserId`

- `(provider, providerUserId)` is the account-linking key, and it now has a **composite unique index**;
  nothing enforced it before.
- A schema migration renames the property; one `ALTER TABLE` renames the column.

## External identity (broker SSO) — Firebase

- `POST /api/auth/external` verifies a broker ID token against the issuer's JWKS and provisions the
  matching vex identity. **Off by default.**
- Every token stays vex-issued: the broker's token is consumed at that one endpoint and never stored.
- No broker SDK on the server, no client secret, no new dependency.
- The generated login page renders the broker's buttons for you — configure it in `vex.config.json`,
  then `npm install` (the `firebase` dependency is new).
- **Use a Web app's config**, all four values from the same registration.
- Configuration, identity rules, troubleshooting: [`docs/features/externalIdentity.md`](../features/externalIdentity.md).

## `sessionCode` is single-use

- `POST /api/auth/token` now consumes the code, instead of leaving it replayable for its whole TTL.

## Login and delete pages

- The home page shows the login link for broker-only apps, which previously had none.
- `/delete_account` states the sign-in prerequisite and links to `/login`.
- `public/js/deleteaccount.js` no longer sends an empty `Bearer ` — **new projects only**, that file is
  copied once and not overwritten.
- The login page's CSP now allows the hosts a broker SDK injects at runtime.

## After upgrading

1. **`npm install`** — `firebase` is a new dependency.
2. **Re-run the generator**, so the schema migration renames the property.
3. **Rename the column and add the constraint:**
   ```sql
   ALTER TABLE "userauthprofiles" RENAME COLUMN "oauthId" TO "providerUserId";
   ALTER TABLE "userauthprofiles" ADD CONSTRAINT "unique_provider_providerUserId"
       UNIQUE ("provider", "providerUserId");
   ```
   `SQL_SYNCHRONIZE=true` covers development. If the old code let two rows claim one identity, find them
   first: `SELECT provider, "providerUserId", COUNT(*) FROM "userauthprofiles" GROUP BY 1,2 HAVING COUNT(*) > 1;`
4. **Update app code** that reads `oauthId`.
5. **Keep `package.json` at `0.9.0` or later** — the migration runner compares the migration's label with
   `.vex/meta.json`'s last generated version, so a lower version re-runs it on every generation.
