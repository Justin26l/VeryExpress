# v0.10.2

## Joins are scoped by the joined document's tenant rule

A `join` used to filter the root document only. The joined rows came back unfiltered, so a row whose
foreign key pointed at another tenant's row returned that row's columns.

The SQL adapter now adds the tenant rule of every joined document as a nested `where` term:

```ts
repo.find({}, ["menuItem"]);        // menuItem.tenantId = :tenantId
repo.find({}, ["menuItem.category"]); // menuItem.tenantId and category.tenantId
```

- Applies to `find`, `findOne`, `findOneWhere` and `findOneWithDeleted`.
- The path is resolved hop by hop against the entity metadata, matching the hop-by-hop check in
  `JoinWhitelistMiddleware`.
- A row whose foreign key points at another tenant is not returned with that row's columns. A
  `findOne` by id returns `null`.
- A joined document that declares no tenant rule joins as before.
- A missing tenant with `onMissing: "deny"` answers `403`, the same as the root document.

Ownership rules (`user._id`) are not applied to joined rows. Joining another user's profile stays
allowed; only tenancy crosses a tenant boundary.

`select`, `pagination`, `$or`, `$and` and the operator DSL are unchanged: the read still goes
through `repo.find`, the join terms are merged into the existing `where`.

## Mongo target

The Mongoose adapter does not implement joins, so this change is SQL-only.

## Generated output

| File | Change |
| --- | --- |
| `_services/TypeOrmRepositoryAdapter.gen.ts` | join isolation terms on the four read methods |

Every scenario's golden output changes: the adapter is a static template copied into every app. An
app with no `tenant.enable` and no isolation rule takes the same query path as before — the registry
lookup returns no rule, so the caller's `where` is passed through untouched.

## Migration

1. Re-run the generator.
2. No schema or config change. A request that joins a tenant-scoped document can now return fewer
   rows when its data holds a foreign key across tenants.

## Tests

`npm test` covers the new adapter source and the regenerated goldens. The join scoping is checked
against a real PostgreSQL: same-tenant join, cross-tenant foreign key, nested path, missing tenant
under `deny`, and `$or` / pagination / `select` interaction. `npm run test:e2e` type-checks the
generated app for every config variant, including the tenant ones.
