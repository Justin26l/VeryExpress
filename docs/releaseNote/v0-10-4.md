# v0.10.4

## Auth templates follow the auth switch

An app with no auth method (`auth.localAuth`, every OAuth provider and `auth.firebase` off) used to
receive the whole auth stack anyway: `Authentication.middleware`, `JWTService`, the login page, the
OAuth runtime, and the `User` / `UserAuthProfiles` / `Session` schemas. None of it could run, and the
three schemas became tables the app never touched.

Those templates are now copied only when an auth method is on. `cleanupStaleFiles` removes them from
an app generated with auth on and re-generated with it off.

## `app.useUserSchema` owns the built-in `User` document

`User.json` is copied only when `app.useUserSchema` is `true` (the default). With `false` the
generator writes nothing:

- a `User.json` already in `jsonSchemaDir` stays untouched and is generated like any other document;
- a project without one emits no `User` table, no `/user` routes and no file that names
  `UserModel`.

`app.useUserSchema` governs the template only. It never deletes or rewrites a file in
`jsonSchemaDir`.

## Auth and RBAC require a `User` document

Auth reads the account row through `UserModel`; `UserRole` declares a foreign key to it. A project
that enables either feature without a document named `User` now stops at generation time:

```
authentication needs a document named "User", and this project has none.
Set "app.useUserSchema" to true to generate the built-in one, or add your own User.json.
```

The check runs before foreign keys resolve, so the failure names the document instead of surfacing
as a relation builder error. `RBAC` is named in the message when `useRBAC` is the reason.

## `auth.verifyOnly`

New mode for a service that serves business routes and validates tokens minted by another vex app:

```jsonc
"auth": { "localAuth": false, "verifyOnly": true }
```

| | Sign-in app | Verify-only app |
| --- | --- | --- |
| `Authentication.gen.ts` | verifies the token, then reads the account row | verifies the token only |
| `JWTService.gen.ts` | mints and verifies, owns sessions | `verifyToken` only |
| `AuthController`, `/login`, OAuth routes | yes | no |
| `User`, `UserAuthProfiles`, `Session` | yes | no |
| `AccountStateGuard.gen.ts` | reads the identity row | constant `true` |

`JWT_SECRET0..9` and `JWT_ALGORITHM` must match the app that signs. Clients send `Authorization`
and `X-Auth-Index` as usual. Identity arrives as the `vexUserId` claim, so `onCreateUserId`,
`onUpdateUserId` and `source: "user._id"` isolation work.

Rejected combinations, each a config error that names the conflict:

| Combination | Reason |
| --- | --- |
| `verifyOnly` with a sign-in method | one app signs in, the other only verifies |
| `verifyOnly` with `useRBAC` | role assignments live in the local `UserRole` table |
| `verifyOnly` with `tenant.IsolationMode: "option"` | selecting a tenant mints a token |

Revocation is bounded by token lifetime: a verify-only app owns no account row to check.

## Tenant membership follows auth

`UserTenant`, `TenantService` and `TenantController` are emitted when the tenant module links
accounts, which requires an auth method. Isolation itself does not: `TenantScope`,
`TenantScopeContext` and every `user.tenantId` rule are emitted from `tenant.enable` alone, and work
with no auth and no account document.

## Generated output

| File | Change |
| --- | --- |
| `_middlewares/Authentication.gen.ts` | emitted with any auth method; verify-only variant reads no account row |
| `_services/auth/JWTService.gen.ts` | emitted with any auth method; verify-only variant has `verifyToken` only |
| `_services/auth/AccountStateGuard.gen.ts` | no-op in verify-only |
| `_middlewares/tsoaAuthentication.gen.ts` | unchanged |
| `_routes/LoginUI.gen.ts`, `_routes/oauth/*`, `_services/oauth/*`, `_types/auth.gen.ts` | emitted only with a sign-in method |
| `_controllers/{Document}Controller.gen.ts` | `@Security` and `Authentication.middleware` when a token is verified |
| `_utils/hash.gen.ts` | no longer imports the `User` type |

## Migration

1. Re-run the generator.
2. An app that keeps auth off and `app.useUserSchema: false` keeps any `User.json`, `Session.json`,
   `UserAuthProfiles.json` or `UserTenant.json` already in `jsonSchemaDir`. Each one still produces a
   document and a table; delete the unused files to drop them.
3. A project with auth or RBAC on and no `User.json` must set `app.useUserSchema: true` or add its
   own schema before the first run of this version.

## Tests

New golden scenarios: `sql-tenant-header-nouser` (auth off, `useUserSchema: false`) and
`sql-verify-only` (verify-only with tenant `preSelect`). New unit tests: `test/unit/authDocuments.test.ts`
for the missing-`User` check and `test/unit/verifyOnly.test.ts` for the mode's predicates and config
validation. `test/e2e/compile.test.ts` adds `tenant-preSelect-auth-off-nouser` and
`tenant-preSelect-verify-only` to the compile matrix.
